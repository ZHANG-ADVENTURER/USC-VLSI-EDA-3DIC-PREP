# Day 41 Daily Log

## Topic

Final Implementation Outputs, PPA Summary, IR-Drop Results, and Signoff Boundaries

## What I Learned

Today I analyzed the final output files and final reports generated by the official Nangate45 GCD OpenROAD flow.

I first classified the major final handoff files:

- `6_final.v` stores the final gate-level logical connectivity.
- `6_final.sdc` stores the final clock and I/O timing constraints.
- `6_final.spef` stores extracted interconnect parasitics.
- `6_final.def` stores placement, routing, pins, special nets, and physical components.
- `6_final.odb` stores the reloadable OpenROAD implementation database.
- `6_final.gds` stores the final layout geometry.

I confirmed that `6_1_merged.gds` and `6_final.gds` have identical SHA-256 checksums. This proves that they are byte-for-byte identical. In contrast, `6_1_fill.odb` and `6_final.odb` have different checksums, so they are not identical serialized databases. The checksum alone does not explain the internal difference.

The final logical netlist preserved the five `clkbuf_*` clock buffers and three `clkload*` dummy clock loads. It did not include `FILLER_*` or `TAPCELL*` instances. This showed the boundary between logical and physical handoff files:

> Final Verilog  
> → functional and clock-tree connectivity

> Final DEF and ODB  
> → complete physical implementation, including filler and tap cells

The final DEF contained 1068 components, 54 bit-level top-level pins, 2 special nets, and 636 regular nets. The two special nets were confirmed as `VDD` with `USE POWER` and `VSS` with `USE GROUND`.

The DEF also defined `CTS_NDR_0`. More importantly, the rule was actively assigned to the top-level clock net `clk` and the shared trunk net `clknet_0_clk`. Therefore, the clock source and shared trunk used a non-default width and spacing rule, while the leaf clock nets were not shown using that rule.

The final SPEF contained 617 `*D_NET` sections, matching the 617 routed nets reported by global routing. The SPEF header identified the design as `gcd`, used IEEE 1481-1999 format, and defined capacitance in pF and resistance in ohms.

I then completed the final PPA summary. The final design used a 0.4600 ns clock constraint and reported +0.0160 ns worst setup slack and +0.1108 ns worst hold slack. Setup and hold TNS were both zero. Maximum slew, fanout, and capacitance violation counts were also zero.

The reported estimated maximum frequency was 2.2523 GHz. This value applies only to the current Nangate45 library, constraints, extracted parasitics, and single timing environment. It is not a silicon guarantee or a multi-corner signoff result.

Final power was 2.45292 mW:

- Internal power: 1.32856 mW
- Switching power: 1.10858 mW
- Leakage power: 0.0157785 mW

Combinational logic contributed 63.3% of total power, sequential logic contributed 24.8%, and the clock network contributed 11.9%. No workload-accurate VCD or SAIF source was confirmed, so the power result is a tool estimate.

The final die area was 1278.42 µm², the core area was 1076.77 µm², and counted instance area was 683.354 µm². Standard-cell utilization was 63.4634%.

The cell-area breakdown showed that the 454 filler cells occupied 393.414 µm². Adding filler area to counted instance area gave approximately the full core area:

> 683.354 µm² + 393.414 µm²  
> = 1076.768 µm²  
> ≈ 1076.77 µm²

This explained why filler cells physically occupy the remaining row area while utilization remains 63.46%. Filler cells are excluded from the utilization numerator.

The static power-grid report confirmed that all VDD and VSS shapes were connected. For VDD, the average IR drop was 1.96 mV and the worst-case IR drop was 5.93 mV, equal to 0.54% of the 1.10 V supply. For VSS, the average ground bounce was 1.80 mV and the worst case was 3.17 mV.

These values are useful baseline results, but they do not establish package-aware, dynamic, multi-corner, or foundry signoff power integrity.

## Key Concepts

### Logical Handoff

A logical handoff describes gates, clock cells, nets, and pin connectivity. It does not contain complete physical-only implementation objects.

### Physical Handoff

A physical handoff preserves placement, routing, pins, special nets, vias, filler cells, tap cells, and implementation geometry.

### SPEF

SPEF stores extracted interconnect resistance and capacitance. It must match the final netlist and be used with timing constraints and Liberty libraries.

### DEF

DEF stores implementation-level physical data such as die area, rows, tracks, components, pins, special nets, routed nets, and non-default rules.

### GDSII

GDSII stores final layout geometry. In this flow, `6_1_merged.gds` and `6_final.gds` were byte-for-byte identical.

### Non-Default Rule

A non-default rule assigns different routing width or spacing to selected nets. `CTS_NDR_0` was used on the clock source and shared trunk nets.

### Utilization

Utilization is counted instance area divided by core area. Filler-cell area was excluded from the utilization numerator.

### IR Drop

IR drop is voltage loss caused by current flowing through resistive power-distribution structures. The reported VDD worst-case drop was 5.93 mV.

## Problems / Fixes

### Problem 1: Equal File Size Was Initially Insufficient

Two GDS files had the same size, but equal size did not prove identical content.

Fix:

I compared their SHA-256 checksums. The hashes matched exactly, proving the files were byte-for-byte identical.

### Problem 2: DEF Via Definitions Could Be Confused with Routed Via Count

The DEF header showed `VIAS 6`, while the routed design contained 3281 vias.

Fix:

I separated via definitions from via instances. `VIAS 6` means six custom via definitions, not six routed vias.

### Problem 3: Filler Cells Appeared in Physical Files but Not Verilog

The final ODB and DEF contained 454 filler cells, while the final Verilog contained none.

Fix:

I treated this as an intentional logical/physical handoff difference. Filler and tap cells are physical-only objects and are not required in the logical gate-level netlist.

### Problem 4: The JSON Average VDD Drop Field Was Misleading

One JSON field labeled as average VDD drop contained a value near the supply voltage.

Fix:

I checked the raw final report instead of trusting the field name. The correct average VDD drop was 1.96 mV, while 1.09804 V was the average VDD voltage.

## Connection to VLSI / EDA / 3D IC

This work directly reflects final Physical Design and signoff-oriented engineering tasks. Engineers must understand which files carry logical data, physical data, parasitics, constraints, and manufacturing geometry.

The PPA summary also shows that a single “final result” is actually a collection of linked artifacts. Timing requires the matching netlist, libraries, SDC, and SPEF. Physical review requires DEF or ODB with technology and cell abstracts. Manufacturing geometry requires GDSII.

For 3D IC and advanced packaging, the same discipline applies across more handoff boundaries. Package and inter-die parasitics, bump models, power-delivery assumptions, and cross-die timing must be tracked with the same care.
