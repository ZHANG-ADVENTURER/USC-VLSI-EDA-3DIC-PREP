# 02 Combinational Logic Modules

## Overview

This project implements three basic Verilog combinational logic modules and verifies them using testbenches and GTKWave waveforms.

The modules include:

* `mux2to1`: a 2-to-1 multiplexer
* `decoder2to4`: a 2-to-4 decoder
* `full_adder`: a 1-bit full adder

The purpose of this project is to practice how Verilog describes hardware behavior and how simulation can be used to verify digital logic.

## Module Description

### `mux2to1`

| Signal | Direction | Width | Description       |
| ------ | --------- | ----: | ----------------- |
| `a`    | input     | 1 bit | First data input  |
| `b`    | input     | 1 bit | Second data input |
| `sel`  | input     | 1 bit | Select signal     |
| `y`    | output    | 1 bit | Selected output   |

In this implementation:

| `sel` | `y` |
| ----: | --- |
|     0 | `b` |
|     1 | `a` |

The multiplexer works like a digital switch. The select signal decides which input is connected to the output.

### `decoder2to4`

| Signal | Direction |  Width | Description            |
| ------ | --------- | -----: | ---------------------- |
| `in`   | input     | 2 bits | Binary input signal    |
| `y`    | output    | 4 bits | One-hot decoded output |

Decoder behavior:

| `in[1:0]` | `y[3:0]` |
| --------- | -------- |
| `00`      | `0001`   |
| `01`      | `0010`   |
| `10`      | `0100`   |
| `11`      | `1000`   |

The decoder converts a binary input into a one-hot output. In GTKWave, the output bus may appear as decimal values `1`, `2`, `4`, and `8`, which correspond to `0001`, `0010`, `0100`, and `1000`.

### `full_adder`

| Signal | Direction | Width | Description      |
| ------ | --------- | ----: | ---------------- |
| `a`    | input     | 1 bit | First input bit  |
| `b`    | input     | 1 bit | Second input bit |
| `cin`  | input     | 1 bit | Carry-in bit     |
| `sum`  | output    | 1 bit | Sum output bit   |
| `cout` | output    | 1 bit | Carry-out bit    |

The full adder performs 1-bit binary addition:

```text
a + b + cin
```

The `sum` output represents the lower bit of the result, and `cout` represents the carry-out bit.

## Testbench

Each module was tested using a separate testbench file. The testbenches provide input stimulus, generate VCD waveform files, and use `$monitor` to print signal values in the terminal.

Test cases:

* `mux2to1_tb.v` tests all 8 combinations of `a`, `b`, and `sel`.
* `decoder2to4_tb.v` tests all 4 combinations of the 2-bit input `in`.
* `full_adder_tb.v` tests all 8 combinations of `a`, `b`, and `cin`.

The simulation commands were run from inside:

```text
01_verilog_basics/02_combinational
```

Example command format:

```powershell
iverilog -o sim/module_tb.vvp src/module.v tb/module_tb.v
vvp sim/module_tb.vvp
gtkwave waveforms/module.vcd
```

## Waveform

Waveform files:

* `waveforms/mux2to1.vcd`
* `waveforms/decoder2to4.vcd`
* `waveforms/full_adder.vcd`

The waveforms show how each output changes in response to different input combinations.

For `mux2to1`, the waveform verifies that `sel = 0` selects `b`, and `sel = 1` selects `a`.

For `decoder2to4`, the waveform verifies that the 2-bit input is decoded into a one-hot 4-bit output.

For `full_adder`, the waveform verifies that `sum` and `cout` correctly represent the result of `a + b + cin`.
