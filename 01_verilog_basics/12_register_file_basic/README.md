# Register File Basic

## Overview

This project implements a basic 4-entry, 8-bit register file in Verilog.

The register file supports one write port and two read ports. The write operation is clocked, while the read operation is combinational.

The main purpose of this project is to understand address-based register access and connect register file structure to datapath design.

A register file is different from a FIFO. A FIFO reads data in first-in-first-out order, while a register file reads data by address.

## Module Description

| Signal | Direction | Width | Description |
|---|---|---:|---|
| `clk` | input | 1 | Clock signal. Write operations happen on the rising edge of the clock. |
| `reset` | input | 1 | Synchronous reset signal. When active, all internal registers are cleared to zero at the clock edge. |
| `write_en` | input | 1 | Write enable signal. When high, `write_data` is written into the register selected by `write_addr`. |
| `write_addr` | input | 2 | Address of the register to write. Supports four registers: `regs[0]` to `regs[3]`. |
| `write_data` | input | 8 | Data value to be written into the selected register. |
| `read_addr1` | input | 2 | Address for read port 1. |
| `read_addr2` | input | 2 | Address for read port 2. |
| `read_data1` | output | 8 | Data output from read port 1. |
| `read_data2` | output | 8 | Data output from read port 2. |

## Testbench

The testbench verifies the basic behavior of the register file.

Test cases:

- Reset the register file and check that all registers read as `00`.
- Write `A1` into `regs[0]` and read it back.
- Write `B2` into `regs[1]` and read both `regs[0]` and `regs[1]`.
- Write `C3` into `regs[2]`.
- Write `D4` into `regs[3]`.
- Read `regs[2]` and `regs[3]` using the two read ports.
- Read the same register from both read ports.
- Overwrite `regs[0]` with `5A` and confirm that `regs[1]` remains unchanged.

The testbench uses task-based checking and prints PASS / FAIL messages in the terminal.

The write operation is checked after a clock edge because writing into the register file is sequential logic.

The read operation is checked after a small delay because this design uses combinational read.

## Waveform

Waveform file: `waves/register_file_basic.vcd`

Waveform screenshot: `waves/register_file_basic_wave.png`

The waveform shows the following behavior:

- `reset` clears the register file.
- `write_en` controls when data is written.
- `write_addr` selects which register is written.
- `write_data` provides the value to store.
- `read_addr1` and `read_addr2` select which registers are read.
- `read_data1` and `read_data2` update according to the selected read addresses.
- The final overwrite operation changes `regs[0]` from `A1` to `5A`.

This waveform confirms that the register file supports clocked write, combinational read, two read ports, and overwrite behavior.
