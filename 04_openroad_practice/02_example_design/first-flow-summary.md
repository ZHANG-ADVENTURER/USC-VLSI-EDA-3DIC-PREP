# First OpenROAD Flow Summary

## 1. Objective

The objective of Day 37 was to run one complete official RTL-to-GDSII example flow before inspecting individual implementation stages in detail.

The selected reference design was:

- Platform: Nangate45
- Design: GCD
- Design configuration: `designs/nangate45/gcd/config.mk`
- RTL source: `designs/src/gcd/gcd.v`

The flow was executed inside the OpenROAD Flow Scripts Docker environment from:

> `/OpenROAD-flow-scripts/flow`

The command used was:

> `make DESIGN_CONFIG=./designs/nangate45/gcd/config.mk`

The run completed successfully and produced the final physical-design database, extracted parasitics, timing constraints, final netlist, DEF, and GDSII output.

## 2. Completed Flow

The completed flow covered the following stages:

> RTL  
> → Yosys synthesis  
> → floorplanning  
> → tap-cell and power-distribution-network insertion  
> → global placement  
> → placement optimization and resizing  
> → detailed placement  
> → clock tree synthesis  
> → global routing  
> → detailed routing  
> → fill-cell insertion  
> → metal fill  
> → GDS merge  
> → final reports

The run produced stage-by-stage OpenROAD database snapshots. These files make it possible to inspect how the design changes after synthesis, floorplanning, placement, CTS, routing, and finalization.

## 3. Runtime Result

The complete example flow finished without a terminating error.

Observed runtime information:

- Total elapsed time: approximately 15 seconds
- Peak memory: approximately 994 MB
- Detailed routing time: approximately 10 seconds

The design is small, so the short runtime is expected. The purpose of this run was to establish a complete implementation workflow rather than to benchmark large-design runtime.

The reported setup result means that the final design met the current maximum-delay timing requirement, but the timing margin was small.

A representative register-to-register setup path had:

- Data arrival time: approximately 0.49 ns
- Data required time: approximately 0.50 ns
- Reported slack: +0.02 ns

A representative minimum-delay path had:

- Data arrival time: 0.19 ns
- Data required time: 0.08 ns

The design also contained register-to-output paths constrained using the virtual clock `vclk_core_clock`.

These results apply only to the current ORFS configuration, library, constraints, mode, and analysis condition. They are not a multi-corner signoff conclusion.

## 11. Main Engineering Lessons

The first complete flow established the connection between previously studied concepts and actual implementation artifacts.

The main relationship is:

> RTL describes behavior.  
> Synthesis creates a standard-cell netlist.  
> Floorplanning defines the physical implementation region.  
> Placement assigns physical locations to cells.  
> CTS builds the clock-distribution network.  
> Routing creates physical interconnect.  
> SPEF captures extracted interconnect parasitics.  
> STA evaluates timing after implementation.  
> GDSII represents the final layout geometry.

The run also demonstrated that implementation is not a single tool action. It is a sequence of database transformations, with reports and logs generated at each major stage.
